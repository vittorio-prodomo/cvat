SAM3 Concept Mode and Indoor v3 Mapping

Two independently testable improvements to CVAT’s AI Tools workflow

2026-09-05 · Approved design · CVAT fork at /data/cvat

Executive summary

The next AI Tools batch adds a concept-search mode to SAM3 and improves default label mapping for Indoor v3. SAM3 will support text alone, a positive exemplar box alone, or both together to find similar objects throughout the submitted image. Indoor v3 will retain its model-native class names while CVAT safely auto-matches unique code prefixes such as C5 to C5_infiltr_cls; Project 40 will receive a generic crack label.

Approved scopeThe two slices share a UI build but remain separate in code, tests, runtime changes, and rollback evidence. Indoor v3 itself does not need a new model image or Nuclio deployment.

Slice A: SAM3 concept and exemplar prompting

User experience

The SAM3 panel presents two explicit modes. Single object remains the default and preserves the existing points/box workflow. Find similar objects uses SAM3’s promptable concept segmentation path and returns multiple candidate masks.

ModeAccepted promptsExpected result
Single objectPositive/negative points and optional starting boxOne mask for the indicated instance
Find similar objectsFreeform text, one positive exemplar box, or bothEvery matching instance above the confidence filter

Freeform text remains primary because project labels may be opaque codes such as C2. A “Use label name” shortcut copies the selected CVAT label into the field, after which it remains editable. The exemplar box is optional so the existing text-only workflow remains available.

Exemplar box versus region of interestThe exemplar says “find objects like this” and does not crop the search. If a CVAT region of interest is also active, CVAT submits only that crop and concept search is necessarily limited to it.

Request and model flow

Select concept mode→ Enter text and/or draw exemplar→ Normalize exemplar box→ SAM3 concept grounding→ Masks + confidence

The client sends an explicit prompt mode so a box-only concept request cannot be confused with single-object box segmentation. Requests without the new mode remain backward compatible: text keeps its current concept behavior and point/box requests keep their current single-object behavior.

The Nuclio handler uses the existing Sam3Processor. It sets the image, applies freeform text when present, converts the exemplar from CVAT pixel xyxy coordinates to SAM3 normalized cxcywh, adds it as a positive geometric exemplar, and serializes all masks and scores through the existing CVAT shape path. The implementation will use SAM3’s public processor operations rather than private model internals.

Result review and refinement

The existing minimum-confidence slider filters the multi-mask result set. Selecting an individual result continues to enable point refinement and real-time erosion/dilation for that one mask. Changing the concept prompt or exemplar starts a new result set and clears selection-specific refinement state.

Options considered

Recommended

Explicit two-mode UI

Maps directly to SAM3’s single-object and concept tasks, keeps the current default, and makes box semantics unambiguous.

Extend the existing Text tab

Smaller visual change, but leaves users to infer why the same box means a single object in one place and an exemplar in another.

One adaptive prompt form

Most compact, but mode changes would occur implicitly as fields are filled and make results harder to predict.

Validation

  • Backend contract tests for text-only, exemplar-only, combined text/exemplar, malformed boxes, and legacy requests.
  • Deterministic adapter tests confirming coordinate conversion, positive exemplar labeling, complete result serialization, and confidence preservation.
  • Frontend tests covering mode transitions, Enter-key submission, ROI coordinate handling, state clearing, confidence filtering, and selected-mask refinement.
  • GPU smoke tests on a controlled image comparing text-only and text-plus-exemplar results, with no annotation writes.

Slice B: Indoor v3 mapping and Project 40

Automatic matching rule

CVAT first retains its existing exact-name match. For an otherwise unmatched model label shaped exactly like C<digits>, it may match a compatible project label beginning with that same code followed by an underscore. The fallback is accepted only when exactly one candidate exists; ambiguity leaves the label unmapped for manual selection.

Indoor v3Project 40 defaultRule
C1C1_difet_esecUnique code-prefix match
C5…C12Corresponding C5_… through C12_…Unique code-prefix match
crackcrackExact match after schema addition
C13—Intentionally unmapped
—C2_efflorescIntentionally unmapped

The delimiter requirement prevents C1 from matching C10_…. Type compatibility remains mandatory, and already-selected/manual mappings remain authoritative.

Project 40 schema addition

Add one project-level label named crack with type any and color #e53935, matching the existing C16–C19 crack family. It receives the same attributes as those labels:

  • mutable select confidence, values low, medium, high, default high;
  • immutable text model_confidence, empty default.

The project-level update makes the label available to all 32 tasks in Project 40. It does not alter existing shapes. Annotators can accept detector output as generic crack and then relabel each instance as C16, C17, C18, or C19.

Options considered

Recommended

Safe UI prefix matching

Preserves truthful model metadata, works across compatible projects, and requires no Indoor v3 redeployment.

Rename the manifest labels

Produces exact matches for Project 40 but couples the detector to one project schema and requires synchronized response-name and Nuclio changes.

Add alias metadata

Most explicit long-term contract, but introduces a new manifest extension and additional parser/UI plumbing for a convention that is already unambiguous.

Validation and mutation safety

  • Unit tests for exact-match precedence, unique prefix matching, C1/C10 boundary safety, ambiguity, incompatible types, C2, and C13.
  • Browser verification that Indoor v3 opens with C1 and C5–C12 pre-mapped, crack exact-mapped, and C2/C13 visibly unmapped.
  • Project schema before/after receipts including label and attribute IDs.
  • Annotation counts checked before and after the schema update; expected annotation writes: zero.

Current live facts used for this design
  • SAM3 is ready and exposes no fixed label specification.
  • Indoor v3 is ready and exposes C1, C5–C13, and crack.
  • Project 40 is “Indoor DOMUS Re-annotation,” has 32 tasks, and currently has no generic crack label.
  • Project 40’s existing non-tag labels already carry model_confidence.
