CVAT SAM3 Runtime Hardening Design

A reproducible, credential-free Nuclio runtime for the existing native SAM3 image interactor.

2026-09-01 · CVAT personal fork · Approved design implemented in an uncommitted worktree; not deployed

Executive summary

Keep the current native SAM3 point-and-box interactor, but replace its drifting runtime and startup-time Hugging Face download with pinned software and a verified local checkpoint. The function will mount the original facebook/sam3 checkpoint read-only, so no Hugging Face token is stored in Nuclio or Docker. Build, import, and GPU-initialization checks are included; live function deployment remains a separate approval boundary.

Approved direction

Native SAM3 code + original sam3.pt + pinned runtime + read-only host mount. SAM3.1, Transformers migration, RF-DETR, commit, push, and live deployment are excluded.

Verified implementation evidence

Independent review drove additional runtime checksum validation, crash-durable checkpoint promotion, a digest-pinned CUDA base, a timestamped Ubuntu snapshot, a complete 58-package Python lock (including the isolated PEP 517 build environment), and a minimal Triton JIT toolchain. Candidate hardening-20260901-r4 (sha256:2ff25e5cbeeb4f9317155910ee6211b1316cbe41cacbab49ac58b593f3739053) completed real point-only and box-only GPU inference with post-processing active; it remains undeployed and uncommitted.

Options considered

Selected

Native SAM3 + local checkpoint

Preserve the tested CVAT adapter and remove runtime authentication and dependency drift.

  • Smallest behavioral change
  • Supports the existing positive/negative point and optional-box contract
  • Deterministic, offline-capable restarts
  • Requires one managed 3.45 GB host artifact

Transformers packaging

Use the current model.safetensors and Transformers processors from the original model repository.

  • Standardized Hugging Face model API
  • Changes the inference adapter and prompt semantics
  • Needs a new compatibility and quality-validation project

SAM3.1 Multiplex

Adopt the newer checkpoint aimed at joint multi-object video tracking.

  • Meaningful video-throughput improvements
  • Not a drop-in image-interactor checkpoint
  • No current benefit for this CVAT image-only workflow

Credential and checkpoint flow

flowchart LR
  A[Fine-grained HF token] -->|one-time authenticated download| B[Temporary download file]
  B --> C{Size and SHA-256 match?}
  C -->|no| D[Delete partial file and fail]
  C -->|yes| E[Atomic rename to /data/cvat/data/models/sam3/sam3.pt]
  E --> F[Read-only bind mount]
  F --> G[Nuclio SAM3 function]
  G --> H[Native interactive predictor]
  A -. never forwarded .-> G
  • The token is entered interactively and exists only for the download process.
  • The destination directory is created with restrictive permissions; downloads use a temporary filename.
  • Size and SHA-256 are checked before atomic promotion to sam3.pt.
  • The Nuclio manifest mounts the containing directory read-only and sets SAM3_CHECKPOINT_PATH to the container path.
  • The generic deployment script no longer needs to forward HF_TOKEN for this SAM3 deployment.

Error handling

FailureRequired behavior
Missing token during one-time downloadFail before network access; never prompt through logs or command arguments.
Denied gated-model accessReport authentication/access failure without echoing credentials.
Interrupted or corrupt downloadKeep only the temporary file; do not replace an existing verified checkpoint.
Missing mounted checkpointFail function initialization with the expected host and container paths.
Checkpoint checksum mismatchRefuse build/probe/deploy and report expected versus observed checksum.
No CUDA device or model-load failureFail explicitly; no CPU fallback and no alternate model.
Nuclio client/dashboard mismatchRefuse live deployment until host nuctl is 1.16.3.

Verification strategy

  1. Red tests: add manifest and model-handler tests for the approved behavior and confirm they fail against the current implementation.
  2. Focused green tests: run the SAM3 Nuclio pytest directory alone, because combining it with similarly named serverless suites causes collection collisions.
  3. Static checks: parse YAML, compile Python, run shell syntax checks, and scan changed files for secrets or unpinned SAM3 URLs.
  4. Checkpoint verification: confirm exact byte size and SHA-256 before any runtime uses the file.
  5. Candidate image build: use matching Nuclio 1.16.3 tooling to build, but not deploy, the function image.
  6. Container import probe: verify Python 3.12, CUDA-enabled PyTorch, torchvision, and the pinned SAM3 package import successfully.
  7. Real GPU inference: initialize the actual interactive predictor on an RTX 6000 Ada, then execute point-only and box-only masks while asserting that Triton post-processing remains active.
  8. Final diff review: confirm only SAM3 hardening artifacts changed and the live Nuclio inventory remains untouched.
Success criterion for this slice

The locked candidate image initializes the real SAM3 interactive predictor and completes point-only and box-only GPU inference with the revalidated local checkpoint, while no Hugging Face token is present in the image or runtime configuration. The function is still not deployed.

Deployment and rollback boundary

After the implementation slice passes, a separate deployment proposal will name the candidate image and exact SAM3-only nuctl deploy command. Before deployment, the host client will be aligned to Nuclio 1.16.3 and the existing empty function inventory will be rechecked. A failed deployment can remove only the named SAM3 function; it does not require rolling back CVAT application containers or touching RF-DETR functions.

Why the original checkpoint is selected instead of SAM3.1

SAM3.1 Object Multiplex is designed around efficient joint multi-object video tracking. The existing CVAT integration is an image-only native interactor that calls SAM3InteractiveImagePredictor with positive points, negative points, and an optional box. The original sam3.pt is the checkpoint used by that native builder path. Adopting SAM3.1 would be a new feature and compatibility project, not a runtime-hardening substitution.
